# Прогнозирование стоимости недвижимости

Проект: модели регрессии для предсказания цены продажи и месячной аренды
объекта недвижимости по датасету **Zingat** (объявления о недвижимости в Турции, 2018–2019).

## Структура проекта

```
real_estate_price/
├── data/
│   ├── real_estate_data.csv     # исходный датасет (403 487 объявлений)
│   ├── test_real_estate_samples.csv  # 20 объектов для проверки модели (Этап 5)
│   └── zingat_data_info.docx    # описание столбцов от авторов датасета
├── real_estate_price.ipynb      # основной notebook: EDA, предобработка, модели, проверка
├── result_real_estate_samples.csv  # прогноз для 20 объектов + ФИО и группа (Этап 5)
├── app.py                       # приложение Streamlit: прогноз, дашборд, справка
├── model.pkl                    # обученная модель + препроцессоры (создаётся notebook-ом, в репозиторий не входит)
├── app_data.csv                 # очищенные данные для дашборда
├── app_metrics.csv              # метрики моделей для дашборда (создаётся notebook-ом)
├── requirements.txt             # версии зависимостей
├── .gitignore                   # исключает большие файлы из репозитория
└── README.md
```

## Запуск

```bash
pip install -r requirements.txt
```

Откройте `real_estate_price.ipynb` и выполните «Run All». Полный прогон занимает
около 25 минут на 16-ядерном процессоре — основное время уходит на подбор
гиперпараметров и обучение стекинга. Нужно около 16 ГБ оперативной памяти.
Notebook создаёт `model.pkl` (около 860 МБ), `app_data.csv`, `app_metrics.csv`
и `result_real_estate_samples.csv`.

После этого запускается приложение:

```bash
streamlit run app.py
```

Приложение откроется в браузере на `http://localhost:8501`.

**Важно:** `model.pkl` весит больше лимита GitHub на размер файла, поэтому
в репозиторий он не входит — его создаёт notebook. Без него приложение
не запустится и скажет об этом явным сообщением.

## Что сделано

| Этап | Содержание |
|---|---|
| Этап 1 | EDA: структура данных, описательные статистики, 6 типов графиков, анализ пропусков, дубликатов и аномалий, гипотезы. Продажа и аренда остаются в данных, тип объявления становится признаком |
| Этап 2 | Очистка данных (строки без площади и с ошибочной площадью сохранены: площадь заполняется медианой по train и отмечается флагами), обработка выбросов цены (свои границы для продажи и аренды), feature engineering, 13 признаков расположения (средние цены по городу, району, кварталу, типу жилья и планировке без утечки), проверка мультиколлинеарности, разбиение 70/15/15 **по объектам**, чтобы копии одного объявления не попадали в train и test одновременно |
| Этап 3 | 6 моделей разной природы (линейная, ближайшие соседи, нейросеть, случайный лес, бустинг, стекинг), подбор гиперпараметров по кросс-валидации по объектам, 4 метрики, сравнительная таблица и графики |
| Этап 4 | Сохранение модели и препроцессоров в `model.pkl`, приложение на Streamlit |
| Этап 5 | Проверка финальной модели на 20 объектах из `test_real_estate_samples.csv`, которые вместе с копиями убраны из данных ещё на Этапе 2: прогноз, MAE/RMSE/R² вручную и через sklearn, анализ, `result_real_estate_samples.csv` |

## Приложение

| Вкладка | Что внутри |
|---|---|
| Прогноз цены | Выбор «продажа / аренда», форма со всеми характеристиками объекта (город, район и квартал), валидация ввода, прогноз с диапазоном ±MAE и ценой за м² |
| Дашборд | KPI, 6 интерактивных графиков с фильтрами по типу объявления, городу, цене и типу жилья, таблица сравнения моделей |
| Справка | Описание приложения и полей, метрики модели, ограничения, версия и авторство |

Модель загружается один раз при старте через `@st.cache_resource`, а не на каждый
запрос. Данные для дашборда кешируются через `@st.cache_data`.

## Модели

| Модель | Тип |
|---|---|
| Ridge | линейная |
| KNeighborsRegressor | ближайшие соседи |
| MLPRegressor | нейронная сеть |
| RandomForestRegressor | ансамбль — бэггинг |
| HistGradientBoostingRegressor | ансамбль — бустинг |
| StackingRegressor | ансамбль — стекинг всех пяти моделей |

Метрики: **MAE**, **RMSE**, **MAPE**, **R²**. Модель обучается на логарифме цены,
метрики считаются в лирах. Тип объявления (`listing_type`: продажа или аренда)
передаётся модели как признак. Масштабирование встроено в линейную модель, соседей
и нейросеть через `Pipeline`.

### Результат

Метрики на validation — новых объектах, копий которых нет в train:

| | MAE | MAPE продажи | MAPE аренды | R² |
|---|---|---|---|---|
| **Стекинг (финальная модель)** | 76 690 | 21.51% | 24.82% | 0.72 |
| Hist-бустинг | 77 803 | 21.80% | 24.98% | 0.72 |
| Случайный лес | 78 162 | 22.03% | 25.28% | 0.70 |
| Нейросеть | 83 646 | 23.88% | 30.11% | 0.68 |
| Ridge | 86 544 | 25.41% | 27.60% | 0.67 |
| Ближайшие соседи | 95 316 | 27.23% | 30.69% | 0.61 |

**Финальная модель** — стекинг: бустинг (вес 0.62), случайный лес (0.25), нейросеть (0.12),
ближайшие соседи (0.02) и Ridge (0), обученные на train. На тестовой выборке:

| | MAE | MAPE | R² |
|---|---|---|---|
| Продажа | 108 858 лир | 21.43% | 0.66 |
| Аренда | 790 лир в месяц | 24.56% | 0.50 |

**Почему метрики ниже, чем в первой версии работы** (там на тесте было MAPE 19–20%
и R² 0.71–0.73). Почти половина объявлений — повторные размещения одного объекта с другой датой.
При случайном разбиении строк у 45% объявлений validation была копия в train, и случайный
лес просто вспоминал цену копии. Теперь данные разделены по объектам, копий в validation
и test нет, и метрики честно показывают качество на новых объектах. На такой проверке
бустинг точнее леса, а стекинг разных моделей — точнее обоих. Больше всего точность подняли
признаки расположения: цена прежде всего зависит от того, где находится объект.

**Этап 5.** На 20 проверочных объектах: продажа — R² 0.72, MAPE 27%; аренда — R² −0.29,
MAPE 77%; все 20 вместе — R² 0.82. Модель видит эти объекты впервые. 16 из 20 — редкие
типы жилья (фермы, виллы, лофты, кооперативы), а R² аренды уводят в минус ферма и лофт
за 16–19 тыс. лир, которые стоят в разы дороже похожих объявлений.

Версии библиотек — в `requirements.txt`.

## Защита от утечки данных

* Признак «цена за м²» намеренно **не используется** — он вычисляется из целевой переменной.
* `tom` (время на рынке) и `end_date` не используются — они становятся известны
  уже после публикации объявления.
* Медианы для заполнения пропусков, One-Hot кодировщик, `StandardScaler` и средние цены
  для признаков расположения считаются **только по train**. Для строк самого train средние
  считаются по частям, без собственного объекта.
* Данные разделены по объектам: копии одного объявления не попадают в разные части
  выборки и в разные фолды кросс-валидации.
* 20 объектов Этапа 5 вместе с копиями убраны из данных до разбиения.
* Тестовая выборка используется один раз, в самом конце.
